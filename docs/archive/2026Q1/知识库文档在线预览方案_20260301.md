# 知识库文档在线预览方案 (支持原生PDF渲染)

> **文件作用**: 为前台知识库管理页面 `/knowledge` 添加点击预览已上传文档的能力，对 PDF 文件支持原生视觉渲染（带图片和排版），其他文件降级为文本预览。
> **更新时间**: 2026-03-01 18:35

---

## 1. 目标分析

**用户诉求**：
在知识库中预览文档时，如果该文档是 PDF，希望能够直接看到 PDF 原本的文件（包括里面的图片和原有排版格式），而不是仅仅展示被大模型引擎提取后的纯文本。

**情况分析**：
- **后端现状**：目前后端仅有 `GET /content` 接口，它利用 LlamaIndex 提取了纯文本。为了让前端能够展示原生 PDF，我们需要在后端直接返回这个物理文件的数据流。
- **前端现状**：现代浏览器普遍内置了优秀的 PDF 渲染引擎，只需要给一个有效的文件 URL 放入 `<iframe src="..." type="application/pdf">` 或 `<object>` 中即可完美渲染原生 PDF。

---

## 2. 后端实施计划

由于原本的 `/content` 接口是提取文本专用的，我们需要新建一个支持直接下发文件流（FileResponse）的接口。

### 2.1 新增静态文件流接口
在 `justime_backend/app/api/v1/endpoints/knowledge.py` 中新增接口：
- `GET /raw`：接收 `path` 参数作为文件名。
- 使用与 `/content` 相同的相对路径安全性校验 `_resolve_safe_document_path`。
- 校验通过后，直接使用 FastAPI 的 `FileResponse` 返回物理文件，并设置恰当的 `media_type`（例如对 PDF 设置 `application/pdf`）。

---

## 3. 前端实施计划

### 3.1 Next.js 代理接口配置
为了使得前端可以跨域拿到文件流，需要在 `justime_agent/src/app/api/knowledge/[...path]/route.ts` 中确保支持把对 `/api/knowledge/raw/文件名.pdf` 的前端请求，代理透传到后端的 `/api/v1/knowledge/raw?path=文件名.pdf`，以供 iframe 使用。
（考虑到已经在同一个通配符 proxy 路由下，可以直接用 URL 拼接方式处理）。 

### 3.2 增加「预览」操作入口
- 修改 `justime_agent/src/app/knowledge/page.tsx`，在列表的单行操作区（Trash2 左边）加入「预览」(Eye Icon) 按钮。
- 点击时根据文件的扩展名区分处理策略：
  - **如果后缀为 `.pdf`**：直接拼装该文件对应的 Next.js raw proxy 路由，如 `/api/knowledge/raw?path={filename}`。
  - **其他后缀（.txt, .md 等）**：仍调用原有的 `/api/knowledge/content?path={filename}` 进行纯文本提取。

### 3.3 文档预览弹窗组件 (智能分流)
- 采用 Radix UI 的 `Dialog` 或全屏弹窗作为容器。
- 弹窗内容根据上面的分类进行渲染：
  - **对于 PDF 预览**：渲染为 `<iframe src="/api/knowledge/raw?path=测试文件.pdf" className="w-full h-[75vh] rounded-md border-0" />`。这会调起浏览器自带的原生阅读器，完美保留原有文字、图像和排版格式。
  - **对于纯文本预览**：显示一个等待动画，请求 `/content` 接口，拿到提取内容后，在 ScrollArea 区域中以明文或 ReactMarkdown 进行渲染。

## 4. 验证计划 (Verification Plan)

### 4.1 渲染格式测试
1. 在前端进行一次文本文件（例如 `test.txt`）上传。
2. 点击 txt 文件的预览，验证能提取文本并展示文本框。
3. 上传一个**包含图片和表格的扫描版或图文混合版 PDF 文件**。
4. 点击 pdf 的预览按钮，观察弹窗内是否显示了和本地打开一样的原本 PDF 文档，包括正确的图片和翻页功能（由浏览器提供）。
