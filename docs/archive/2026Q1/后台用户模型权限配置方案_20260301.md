# 后台用户模型权限配置方案

> **文件作用**: 为管理后台添加用户级别的模型访问权限控制功能，允许管理员对不同用户开放不同的模型。
> **创建时间**: 2026-03-01 16:00

---

## 1. 目标分析

**用户诉求**：
想要向不同的用户选择不同的模型开放，并且配置选项在后台管理的用户管理版块（`/admin/users`）。

**核心改动点**：
1. **用户数据模型扩展**：在 MongoDB `users` 集合中增加模型访问权限字段，例如 `access_all_models` 和 `allowed_model_ids`。
2. **后台 API 扩展**：增加一个可以修改用户模型权限的接口 `PUT /admin/users/{user_id}/models`。
3. **系统模型拉取拦截**：在前端用户获取可用模型列表，以及后端执行聊天逻辑时，读取当前用户的权限并过滤掉无权访问的模型。
4. **前端后台界面交互**：在用户管理界面中为每个用户加入「配置模型权限」的弹窗，可以开关「允许访问所有模型」或单独勾选允许访问的模型。

---

## 2. 后端实施计划

### 2.1 扩展 User Schema 与 DB 逻辑
- **改造 `justime_backend/app/models/admin.py`**：
  - 在 `AdminUser` 中增加 `access_all_models: bool` 和 `allowed_model_ids: List[str]`。
  - 新增 Request Schema `UserModelAccessUpdateRequest`，包含上述两个字段。
- **改造 `justime_backend/app/business/admin_business.py`**：
  - 在获取用户列表时，读取 `access_all_models`（默认为 True）和 `allowed_model_ids`（默认为空数组）。
  - 新增 `update_user_model_access(user_id, access_all_models, allowed_model_ids)` 到业务层和 `UserService` 中更新 DB。

### 2.2 新增后台修改权限接口
- **在 `justime_backend/app/api/v1/endpoints/admin.py` 中新增**：
  - `PUT /admin/users/{user_id}/models`：更新目标用户的可用模型白名单。

### 2.3 核心聊天及查询逻辑的鉴权拦截
- **改造系统模型下发接口**：
  - 当前用户查询模型列表时（假设通过 `GET /v1/models` 或直接由前端拉取），后端需获取该当前用户的权限并做交集过滤。
  - 将 `UserService.get_system_llm_configs` 修改为或包装成一个针对某用户的 `get_available_models_for_user(user_id)`：
    - 如果 `user.access_all_models == True`，则返回所有 enabled 的 `system_llm_configs`。
    - 否则，仅返回 ID 存在于 `user.allowed_model_ids` 中的 `system_llm_configs`。
- **聊天请求强校验** (`agent_service.py` 等位置)：
  - 发端时验证当前 `model_id` / `config_id` 是否在用户允许的列表内，避免越权抓包调用。

## 3. 前端界面实施计划

### 3.1 用户管理后台修改（`/admin/users/page.tsx`）
- **触发入口**：
  - 在操作列的 DropdownMenu 中，新增一个菜单项：「配置模型权限」 (ShieldCheck Icon)。
- **配置弹窗**：
  - 打开后并行请求获取系统的所有模型（`/api/admin/models`），弹出一个 Dialog，列出用户名称。
  - **交互 1**：一个 Switch 开关“允许访问所有模型”。默认打开。
  - **交互 2**：如果 Switch 关闭，展示一个包含所有系统模型的 Checkbox 列表，管理员可以勾选该用户被允许访问的个别模型。
  - 提交后调用 `PUT /api/admin/users/{user_id}/models` 保存状态，并刷新列表中对应的状态。

### 3.2 代理 API 增加透传接口
- 在 `justime_agent/src/app/api/admin/users/[userId]/models/route.ts` 中新增 PUT 方法以连接到 FastAPI 后端对应的接口。

## 4. 验证计划 (Verification Plan)

### 4.1 手工验证测试
1. **超级管理员分配测试**：
   - 登录后台系统，进入「用户管理」。
   - 对于普通测试用户，点击「配置模型权限」，关闭「允许访问所有模型」，只给其分配一个测试模型甲 (`Model A`) 并保存。
   - 确认请求成功保存且不影响其他用户。
2. **普通用户权限降级测试**：
   - 使用上述普通用户账号登录前台（或新开无痕窗口模拟其环境）。
   - 查看模型下拉列表，断言**只显示了 `Model A`**。
   - 尝试通过该用户的页面向该被允许的模型发起对话，应当成功。
3. **普通用户越权拦截测试**：
   - 普通用户尝试强行修改请求负载去请求一个未被授权的模型 `Model B`。
   - 断言后端抛出如 `403 Forbidden` 或 `Model Access Denied` 等明确错误，而非静默成功。
