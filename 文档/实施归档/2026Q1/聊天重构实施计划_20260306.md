# 移动端 AI 聊天主页 (index.tsx) 重构实现计划

## 🎯 目标与背景
当前 `/mobile/justime_mobile/app/(tabs)/index.tsx` 文件代码量超过 1600 行，承担了过多的指责，不仅导致代码可读性极差，难以维护，还存在严重的性能隐患（例如输入框内容改变会触发整个复杂页面的重渲染）。

本计划旨在指导（如 Codex 等 AI）通过**“逻辑与视图分离”、“组件化拆分”**的原则，对该页面进行彻底重构，将其打造成一个高性能、易维护的 React Native 现代化组件架构。

---

## 📂 阶段一：逻辑抽离 (Custom Hooks)

当前 `index.tsx` 中包含了大量的状态定义（如 `messages`, `sessionId`, `loading` 等）和业务方法（如 `handleSend`, `loadSessions`, `handleAuth`）。

**操作步骤：**
1. 在 `mobile/justime_mobile/hooks/` 目录下新建 `useChatScreenLogic.ts`。
2. 将 `index.tsx` 所有的 `useState`, `useEffect`, `useCallback` 以及纯业务逻辑函数（如网络请求、数据清洗、缓存处理）全部迁移至此 Hook。
3. 对外暴露一个包含状态（如 `messages`, `sessions`, `isLoggedIn` 等）和操作函数（如 `sendMessage`, `login`, `createSession` 等）的对象。

---

## 🧱 阶段二：UI 组件拆分 (Dumb Components)

在 `mobile/justime_mobile/components/chat/` 目录下，按照单一职责原则拆分以下独立组件：

### 1. `AuthOverlay.tsx` (认证与连通性页面)
*   **职责：** 处理用户未登录状态下的视图。
*   **内容：** 包含选择登陆/注册的 Tabs，邮箱/密码输入框，连通性测试按钮以及认证相关的提示信息。
*   **Props 接口：** 接收 `onLogin`, `onRegister`, `onTestConnection` 等回调函数和错误信息状态。

### 2. `ChatInputBox.tsx` (底部聊天输入框)
*   **职责：** 专注于处理用户的文字输入与发送交互。
*   **性能关键点：** 将控制输入框文字的状态 (`input`) 独立在这个组件内部。这样用户高频敲击键盘时，只会触发该组件自身的小范围重渲染，绝不会影响上方承载几百条历史记录的主列表。
*   **Props 接口：** 接收 `onSend`, `loading`, `useWebSearch` 状态和对应的 toggle 方法。

### 3. `ChatMessageList.tsx` (消息列表展示)
*   **职责：** 渲染聊天记录。
*   **内容：** 封装 `<FlatList>`，并将单条消息的渲染逻辑 (`renderItem`) 或独立的 `<ChatMessageItem />` 放入其中。处理滚动到最新消息的动画。
*   **Props 接口：** 接收 `messages` 数组，以及交互卡片（添加日程、关闭卡片）相关的回调事件。

### 4. `ChatHeader.tsx` (顶部导航护栏)
*   **职责：** 渲染当前大模型状态、用户问候语以及唤起历史会话入口。
*   **Props 接口：** 接收 `userDisplayName`, `selectedModelLabel`, `onOpenHistory`, `onOpenModelPicker`。

### 5. `HistorySessionModal.tsx` & `ModelPickerModal.tsx` (模态弹窗)
*   **职责：** 剥离子视图，分离弹窗代码。
*   **内容：** 分别迁移原生 `<Modal>` 中的历史会话列表和模型选择列表UI。

---

## 🏗 阶段三：主入口组装 (Smart Component)

清洗原本的 `mobile/justime_mobile/app/(tabs)/index.tsx` 文件。经过重构后，此文件应只保留极少的代码行数，职责单纯退化为**“协调器（UI 组装与状态分发）”**。

**重构后的目标结构示意图 (伪代码)：**

```tsx
import React from 'react';
import { SafeAreaView, KeyboardAvoidingView } from 'react-native';
import { useChatScreenLogic } from '@/hooks/useChatScreenLogic';

// 导入拆分的子组件
import AuthOverlay from '@/components/chat/AuthOverlay';
import ChatHeader from '@/components/chat/ChatHeader';
import ChatMessageList from '@/components/chat/ChatMessageList';
import ChatInputBox from '@/components/chat/ChatInputBox';
import HistorySessionModal from '@/components/chat/HistorySessionModal';
import ModelPickerModal from '@/components/chat/ModelPickerModal';

export default function ChatScreen() {
  const logic = useChatScreenLogic(); // 初始化所有业务状态与方法

  // 1. 拦截未登录状态
  if (!logic.isLoggedIn) {
    return <AuthOverlay {...logic.authProps} />;
  }

  // 2. 渲染主骨架
  return (
    <SafeAreaView style={styles.container}>
      <KeyboardAvoidingView behavior="padding" style={styles.flex}>
        
        {/* 顶部状态栏 */}
        <ChatHeader {...logic.headerProps} />

        {/* 聊天记录列表 (不关心自身如何滚动和渲染) */}
        <ChatMessageList {...logic.listProps} />

        {/* 底部输入框 (内部消化打字重渲染) */}
        <ChatInputBox {...logic.inputProps} />

      </KeyboardAvoidingView>

      {/* 弹窗层 */}
      <HistorySessionModal {...logic.historyModalProps} />
      <ModelPickerModal {...logic.modelModalProps} />
      
    </SafeAreaView>
  );
}
```

## ⚠️ Codex 执行注意事项

1. **严格类型约束：** 重构时不允许丢失 TypeScript 类型（如 `ChatMessage`, `TaskDecomposition`）。请将全局类型的定义提取到 `mobile/justime_mobile/types/chat.ts` 中单独维护。
2. **样式隔离：** 各个拆分出来的 UI 组件对应的 `StyleSheet` 应紧跟该组件一并迁移，不要遗漏。
3. **动画遗留：** 聊天主页中使用了大量的 `LayoutAnimation.configureNext` 保证原生流畅过渡，在抽离给 `ChatInputBox` 等组件点击发送的事件回调时，请确保依然能触发该布局动画。
