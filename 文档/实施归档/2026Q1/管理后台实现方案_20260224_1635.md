# 管理后台 (Admin Dashboard) 实现方案

> **文件作用**: 管理后台新功能的详细全栈实现计划  
> **创建时间**: 2026-02-24 16:35

---

## 1. 目标与需求分析

**当前状态**：
- 前端已有 `/admin` 路由（概览页）和 `/admin/users` 路由（用户列表页的壳子），并包含响应式布局侧边栏（`layout.tsx`）。
- 后端已有基础的 `/admin/users` 和 `/admin/stats` 接口（`app/api/v1/endpoints/admin.py`），且已连接 `admin_business` 业务层。

**目标需求**：
实现一个完整的管理员（role === 'admin'）看板，支持：
1. **用户管理**：展示所有用户、封禁/启用账号、删除用户、修改用户角色（提升为管理员）。
2. **模型配置管理**：管理系统的全局 LLM 模型（对应数据库 `system_llm_configs` 表），支持增删改查（CRUD）。
3. **数据大盘展示**：概览全站 Token 消耗、活跃用户数、历史会话数。

---

## 2. 数据库设计与现有表映射

根据 Docker 中的 MongoDB 数据结构：
- **`users` 表**：需操作字段 `role` (user/admin), `status` (active/banned)。
- **`system_llm_configs` 表**：存储全局平台默认模型列表。
- **`llm_token_usage_daily` 表**：提供 `/admin/stats` 的实时 Token 计算。

---

## 3. 后端 (FastAPI) 实现步骤

### 3.1 补充 User 管理接口
**文件**: `justime_backend/app/api/v1/endpoints/admin.py` & `justime_backend/app/business/admin_business.py`
- **[已存在]** `GET /admin/users`: 返回所有用户列表。
- **[已存在]** `DELETE /admin/users/{user_id}`: 删除用户。
- **[新增]** `PUT /admin/users/{user_id}/status`: 禁用或启用特定用户。
- **[新增]** `PUT /admin/users/{user_id}/role`: 修改用户角色（转为 `admin` 或 `user`）。

### 3.2 新增 System Models 管理接口
**文件**: `justime_backend/app/api/v1/endpoints/admin.py`
- **[新增]** `GET /admin/models`: 获取 `system_llm_configs` 所有全局配置。
- **[新增]** `POST /admin/models`: 添加新的全局模型配置（如新上架一个模型供应商）。
- **[新增]** `PUT /admin/models/{model_id}`: 修改指定的全局模型配置（支持修改 base_url, 优先级等）。
- **[新增]** `DELETE /admin/models/{model_id}`: 删除指定的全局模型配置。

### 3.3 补全数据统计逻辑
**文件**: `justime_backend/app/business/admin_business.py`
- 修改 `get_system_stats` 方法：不再返回 Mock 的 `1500000` Token 用量，而是通过 MongoDB 聚合查询 `llm_token_usage_daily` 获取真实的全平台 Token 和历史会话数量。

## 4. 前端 (Next.js) 实现步骤

### 4.1 完善用户管理页面 (`/admin/users/page.tsx`)
- 使用 Shadcn UI 的 `Table` 组件渲染用户列表（用户名、邮箱、角色、状态、最后登录时间）。
- 在操作列增加下拉菜单 (`DropdownMenu`)，提供选项：【提升为管理员/降级】、【禁用/启用账户】、【删除账户】。
- 绑定对应的 `PUT` / `DELETE` API，完成后刷新表格。

### 4.2 开发模型管理页面 (`/admin/settings/page.tsx` 或新建 `/admin/models/page.tsx`)
- **展示**：使用卡片或表格展示系统中所有公共 LLM 配置。
- **新增配置**：提供 `Dialog` 弹窗弹出一个表单，输入 `name`（展示名）、`model_id`、`api_key`、`base_url`、`capabilities`。
- **状态切换**：通过 `Switch` 组件一键启用/禁用某个底层模型（更改 `enabled` 字段）。
- **编辑与删除**：允许管理员随时调整供应商密钥或下线某个模型。

### 4.3 修正导航与权限拦截 (`/admin/layout.tsx`)
- 确保侧边栏的路由项包含：“概览仪表盘”、“用户管理”、“系统模型管理”。
- 当前的权限拦截逻辑 `user.role !== 'admin'` 已经很完善，维持现状即可。

## 5. 验证计划

1. **权限验证**：
   - 登录一个普通用户账号，访问 `/admin`，预期被中间件拦截或显示“访问被拒绝”。
   - 将该用户数据库里的 `role` 字段改为 `admin`，重新登录并访问 `/admin`，预期顺利进入管理大盘。
2. **接口联调**：
   - 在前端点击“禁用账号”，检查发出的是否是对应的 `PUT` 请求，且数据库中 `status` 被标记为非活跃。
   - 在模型配置页面新建一个测试供应商模型，打开普通的“模型配置页 (Client端)” 验证这新增的模型是否能被普通用户使用。
3. **数据一致性**：
   - 查看仪表板上的 Token 消耗，使用聚合语句 `db.llm_token_usage_daily.aggregate([{ $group: { _id: null, total: { $sum: "$totalTokens" } } }])` 在数据库核对数字是否完全吻合。
