## 问题 1：「默认配置 / deepseek」多余条目

### 根因

后端 `chat_business.py` 记录模型使用量时，`config_id` 的取值存在回退逻辑：

```python
# chat_business.py 第 785 行 (classifier 调用)
config_id=classifier_runtime.get("config_id") or "legacy-default"
config_name=classifier_runtime.get("config_name") or "默认配置"

# chat_business.py 第 908 行 (main 调用)
config_id=main_runtime.get("config_id") or "legacy-default"
config_name=main_runtime.get("config_name") or "默认配置"
```

在早期版本或特定场景下，`config_id` 可能是 `"platform-default"` 或 `"legacy-default"`，而非系统配置中的标准 ID（如 `sys-deepseek-chat`）。

当 `get_llm_daily_usage` 聚合统计时（[auth_business.py](file:///Users/zhuyuxuan/Desktop/Code/justime/justime_backend/app/business/auth_business.py#L376-L389)），遇到不匹配任何 `system_llm_configs` 的 `configId`，会创建额外条目：

```python
if config_id not in models_map:
    models_map[config_id] = {
        "configId": config_id,
        "name": row.get("configName") or "历史配置",  # ← 取值为 "默认配置"
        "modelId": row.get("modelId") or "",           # ← 取值为 "deepseek"
        ...
    }
```

因此「默认配置 / deepseek」是来自历史使用记录的**孤立数据**。

### 修复方案

**修改文件**: `justime_backend/app/business/auth_business.py`

在 `get_llm_daily_usage` 方法中，对不匹配系统配置的 usage 行尝试**模糊归并**到已知配置，而非创建新条目：

```python
# 第 376-389 行修改
for row in usage_rows:
    config_id = row.get("configId") or "unknown"
    usage_date = row.get("date")
    if usage_date not in date_series:
        continue

    # 若 config_id 不在 models_map 中，尝试按 modelId 模糊匹配已有系统配置
    if config_id not in models_map:
        row_model_id = (row.get("modelId") or "").lower()
        matched_key = None
        for key, entry in models_map.items():
            if entry.get("modelId", "").lower() == row_model_id:
                matched_key = key
                break
        if matched_key:
            config_id = matched_key  # 归并到已知系统配置
        else:
            # 无法匹配，仍创建独立条目（但标记为历史数据）
            models_map[config_id] = {
                "configId": config_id,
                "name": row.get("configName") or "历史配置",
                "modelId": row.get("modelId") or "",
                "isActive": config_id == active_id,
                "_daily_map": init_daily_points()
            }

    models_map[config_id]["_daily_map"][usage_date] = { ... }
```

这样，`configId` 为 `"legacy-default"` 但 `modelId` 为 `"deepseek-chat"` 的历史记录会归并到 `sys-deepseek-chat` 的条目中。

## 问题 2：柱状图每天底部有小段显示

### 根因

[page.tsx](file:///Users/zhuyuxuan/Desktop/Code/justime/justime_agent/src/app/model-config/page.tsx#L258) 第 258 行：

```tsx
const barHeight = Math.max(3, Math.round((point.totalTokens / maxToken) * 100))
```

`Math.max(3, ...)` 强制最小柱高为 3%，即使当天 `totalTokens = 0`，也会显示 ~3px 的小段。

### 修复方案

**修改文件**: `src/app/model-config/page.tsx`

当 `totalTokens` 为 0 时，柱高设为 0；仅有数据时保留最低可见高度：

```diff
- const barHeight = Math.max(3, Math.round((point.totalTokens / maxToken) * 100))
+ const barHeight = point.totalTokens > 0
+   ? Math.max(3, Math.round((point.totalTokens / maxToken) * 100))
+   : 0
```

## 问题 3：添加柱状图上的数值标签

### 现状

当前柱状图仅在鼠标悬停时通过 tooltip 显示数据。需要在每根柱条上（或柱条顶部）显示 Token 数值。

### 修复方案

**修改文件**: `src/app/model-config/page.tsx`

在 `renderUsageModelCard` 函数的柱条渲染区域（约第 260-272 行），在每根柱条的**顶部**添加数值标签：

```diff
 <div
   key={`${model.configId}-${point.date}`}
   className="flex-1 h-full rounded-sm bg-white/5 relative overflow-hidden group"
 >
   {/* Tooltip (保持不变) */}
   <div className="absolute opacity-0 group-hover:opacity-100 ...">...</div>
+
+  {/* 柱条顶部数值标签 */}
+  {point.totalTokens > 0 && (
+    <div
+      className="absolute left-1/2 -translate-x-1/2 text-[8px] text-white/60 whitespace-nowrap pointer-events-none select-none"
+      style={{ bottom: `${barHeight + 2}%` }}
+    >
+      {formatTokenValue(point.totalTokens)}
+    </div>
+  )}
+
   {/* 柱条本体 */}
   <div
     className="absolute bottom-0 left-0 right-0 rounded-sm bg-indigo-400/80 ..."
     style={{ height: `${barHeight}%` }}
   />
 </div>
```

**设计细节**：
- 字号 `text-[8px]` 避免在柱条密集时重叠
- `bottom: ${barHeight + 2}%` 使标签浮在柱条顶部上方
- `totalTokens > 0` 时才显示，避免 0 值刷屏
- 使用 `formatTokenValue()` 格式化为 `K` / `M` 单位
