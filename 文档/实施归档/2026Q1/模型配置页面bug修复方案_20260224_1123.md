## Bug 1: Token 用量图表不显示

### 现象
右侧面板中的 Token 使用量柱状图完全未展示。

### 根因分析
当前 `page.tsx` 中图表的渲染逻辑（约第 405 行）要求 **同时满足两个条件**：
1. `selectedModelId` 不为空（用户必须点击左侧某个模型）
2. `selectedUsageModel` 存在（该模型在 usage API 中有对应数据）

当没有选中任何模型时（默认状态），页面只展示一个汇总卡片（模型数量 / 累计 Token / 总请求次数），**不会展示任何柱状图**。

> 相关代码：`page.tsx` 第 379-397 行（汇总卡片）和第 405-452 行（柱状图，需 selectedUsageModel）

### 修复方案

**修改文件**: `src/app/model-config/page.tsx`

在未选中模型的默认状态下（`!selectedModelId`），除展示汇总卡片外，**额外展示所有非 GPT 模型的柱状图列表**，与原来页面的全量展示效果一致。

具体改动：
- 在第 397 行的汇总卡片闭合 `</div>` 后，新增一个 `filteredUsageModels.map(...)` 循环，渲染每个模型的柱状图
- 当 `selectedModelId` 为空时展示所有模型图表，选中时仅展示选中模型图表（现有逻辑保持不变）

## Bug 2: 调整 Temperature 时 404 报错

### 现象
调整 Temperature 滑块后，控制台报错：
```
PUT http://localhost:3000/api/auth/llm-configs/sys-deepseek-reasoner 404 (Not Found)
```

### 根因分析（完整链路）

```
前端 page.tsx → useLLMConfigs.updateConfig(id, { temperature })
  → fetch(`/api/auth/llm-configs/${id}`, { method: 'PUT' })
    → Next.js proxy route: src/app/api/auth/llm-configs/[id]/route.ts
      → fetch(backendUrl: `/auth/llm-configs/${id}`, { method: 'PUT' })
        → ❌ 后端无此路由 → 404
```

**根本原因**：后端 `auth.py` 只定义了以下两个 `llm-configs` 路由：
| 方法 | 路由 | 功能 |
|------|------|------|
| `GET` | `/auth/llm-configs` | 获取配置列表 |
| `PUT` | `/auth/llm-configs/{config_id}/active` | 激活指定配置 |

**缺少** `PUT /auth/llm-configs/{config_id}` 路由来支持更新单个配置的参数（如 temperature）。

**同时**，`get_llm_configs_list` 方法返回的 `safe_configs` 中也**未包含 `temperature` 字段**，导致即使修复了更新接口，前端也无法获取到当前的 temperature 值。

### 修复方案

需要修改 **3 个文件**：

---

#### 文件 1: `justime_backend/app/api/v1/endpoints/auth.py`

**改动**: 新增 `PUT /llm-configs/{config_id}` 路由

```python
@router.put("/llm-configs/{config_id}", response_model=AuthResponse, summary="更新指定配置参数")
async def update_llm_config(
    config_id: str,
    payload: dict,
    current_user: Dict[str, Any] = Depends(SecurityService.get_current_user)
) -> AuthResponse:
    """更新指定系统模型配置的可调参数（如 temperature）"""
    user_id = str(current_user["_id"])
    return await auth_business.update_system_config(config_id, payload)
```

> **注意**: 此路由应放在 `PUT /llm-configs/{config_id}/active` **之前**，以避免 FastAPI 路径匹配冲突。但由于 FastAPI 匹配时 `/active` 是精确路径段而非路径参数，顺序不影响。放在 `@router.put("/llm-configs/{config_id}/active"...)` 之后即可。

#### 文件 2: `justime_backend/app/business/auth_business.py`

**改动 A**: 新增 `update_system_config` 方法

```python
@staticmethod
async def update_system_config(config_id: str, payload: dict) -> AuthResponse:
    """更新系统模型配置的可调参数"""
    allowed_fields = {"temperature"}
    updates = {}
    for key in allowed_fields:
        if key in payload:
            updates[key] = payload[key]

    if not updates:
        return AuthResponse(success=False, message="没有可更新的参数")

    # 校验 temperature 范围
    if "temperature" in updates:
        temp = updates["temperature"]
        if not isinstance(temp, (int, float)) or temp < 0 or temp > 2:
            return AuthResponse(success=False, message="temperature 必须在 0.0 ~ 2.0 之间")
        updates["temperature"] = float(temp)

    from app.database import db
    result = await db.db.system_llm_configs.update_one(
        {"id": config_id},
        {"$set": updates}
    )
    if result.matched_count == 0:
        return AuthResponse(success=False, message=f"未找到配置 {config_id}")

    return AuthResponse(success=True, message="更新配置成功")
```

## 验证计划

### 手动验证

1. **重启后端**：修改后重启后端服务（`python start.py`）
2. **刷新前端**：访问 `http://localhost:3000/model-config`
3. **验证图表展示**：
   - 不点击任何模型 → 应同时看到汇总卡片和所有非 GPT 模型的柱状图
   - 点击某个模型 → 仅展示选中模型的柱状图
   - 点击「查看全部」→ 恢复全量展示
4. **验证 Temperature 设置**：
   - 选中一个模型（如 DeepSeek Chat）
   - 拖动 Temperature 滑块 → 确认无 404 报错，出现「已自动保存」提示
   - 刷新页面 → 重新选中该模型 → 确认 Temperature 值已持久化
5. **验证 temperature 回显**：
   - 选中模型后，确认 Temperature 滑块显示的值与后端存储值一致
