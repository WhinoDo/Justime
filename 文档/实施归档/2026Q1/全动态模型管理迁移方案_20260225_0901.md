# 纯动态模型管理迁移与实现方案

> **文件作用**: 彻底废弃硬编码与 `.env` 中配置的大模型池，改为完全由「管理后台」通过数据库动态管理的详细方案。  
> **创建时间**: 2026-02-25 09:01

---

## 1. 目标分析

目前系统中存在两套模型配置获取逻辑：
1. **主要聊天功能**: 从 MongoDB 的 `system_llm_configs` 表获取，但也保留了一些 `init_system_models.py` 的硬编码后备。
2. **后端 Agent 调用 (如 `agent_service.py`)**: 还在通过 `settings.get_llm_configs()` 从本地环境变量 (`LLM_PROVIDERS` / `.env`) 强制读取静态配置。

**用户诉求**：**清除并废弃所有预设/环境变量中的硬编码模型，系统 100% 只信任并读取来自于 MongoDB `system_llm_configs` (即管理员在页面配置) 的模型池。**

---

## 2. 后端迁移实施计划

### 步骤 2.1：统一模型获取源
修改所有绕过数据库直接读本地配置的代码，使其全部指向数据库：
- **修改 `justime_backend/app/services/agent_service.py`**：
  将第 97 行和 132 行的 `configs = settings.get_llm_configs()` 
  替换为异步获取数据库配置：`configs = await UserService.get_system_llm_configs()`。
   *(注：需要处理返回值类型从 Dict 到 List 的转换兼容)*

### 步骤 2.2：处理“数据库为空”的容错逻辑
当管理员还没有配置任何模型、或者删除了所有模型时（系统处于「模型真空期」）：
- **后端兜底处理**:
  如果 `system_llm_configs` 为空，接口不再抛错，而是返回空数组 `[]`。
  如果前端用户尝试强行发送聊天请求，抛出明确的提示：`"平台尚未配置可用的 AI 模型，请联系管理员添加。"`
- **前端兜底处理** (`src/app/model-config/page.tsx`)：
  如果获取到的 `filteredConfigs` 长度为 0，页面应显示骨架屏或清晰提示：`"暂无可用模型，请等待系统管理员配置。"`。

### 步骤 2.3：后台模型管理 API 开发 (沿用前置方案)
在 `justime_backend/app/api/v1/endpoints/admin.py` 中激活四个关键接口：
- `GET /admin/models`
- `POST /admin/models` (新建)
- `PUT /admin/models/{model_id}` (修改)
- `DELETE /admin/models/{model_id}` (删除)

---

## 3. 前端界面实现计划

### 步骤 3.1：后台模型管理大盘 (`/admin/models/page.tsx`)
实现以下可视化能力：
1. **空状态呈现**: 没有任何模型时，显示大大的一键「添加首个模型」引导按钮。
2. **表格展示**: 展示已存入数据库的提供商、模型ID、Base URL。
3. **添加弹窗**: 表单包含（展示名 Name、Model ID、Base URL、API Key、能力标签）。
4. **即时通讯**: 提交保存后立即请求 `POST` 接口，写入 MongoDB。

---

## 4. 落地清理工作 (Execution Phase)

1. 通过脚本直接清空目前 MongoDB 的 `system_llm_configs` 集合（`db.system_llm_configs.deleteMany({})`）模拟全空状态。
2. 删除废弃的 `init_system_models.py` 脚本，避免之后不小心执行又把旧模型刷回数据库。
3. 去除 `app/core/config.py` 中关于 `LLM_PROVIDERS` 等废弃的配置。
