# 系统模型管理模块实现方案

> **文件作用**: 管理后台「系统模型配置」页面的前后端详细开发计划  
> **创建时间**: 2026-02-24 18:55

---

## 1. 现状分析

通过审阅代码，我发现在后端业务层（`jushi_backend/app/business/admin_business.py`）**其实已经预先写好了对于系统模型的增删改查逻辑**：
- `get_all_models()`
- `create_model(payload)`
- `update_model(model_id, payload)`
- `delete_model(model_id)`

并且在底层，所有用户的聊天界面模型下拉列表，都是通过 `UserService.get_system_llm_configs()` 从数据库的 `system_llm_configs` 集合中实时读取的。

**因此，我们只需要**：
1. 把这些已经写好的后端业务方法，暴露成 API 接口供前端调用。
2. 在前端管理后台写一个页面来调用这些接口，提供可视化的表单即可。

---

## 2. 后端实现计划 (FastAPI)

**目标文件**: `jushi_backend/app/api/v1/endpoints/admin.py`

在管理员专属的网关中新增以下 4 个 API 端点：

1. **`GET /admin/models`** 
   - 作用：获取所有系统模型列表，直接调用 `admin_business.get_all_models()`。
2. **`POST /admin/models`**
   - 作用：新建模型。接收 JSON Payload（包含 `name`, `model_id`, `base_url`, `api_key`, `capabilities` 等）。
   - 逻辑：通过 `admin_business.create_model()` 写入数据库（API Key 会自动被加密）。
3. **`PUT /admin/models/{model_id}`**
   - 作用：修改现有模型参数（如更改 URL 或 更新 Key）。
4. **`DELETE /admin/models/{model_id}`**
   - 作用：将模型从系统下架删除。

## 3. 前端实现计划 (Next.js)

### 3.1 增加侧边栏导航入口
**目标文件**: `jushi_agent/src/app/admin/layout.tsx`
- 在 `menuItems` 数组中增加一项：
  ```javascript
  {
      title: '模型管理',
      icon: ServerCog, // 或其他合适的 Lucide icon
      href: '/admin/models'
  }
  ```

### 3.2 创建模型管理页面
**目标文件**: 新建 `jushi_agent/src/app/admin/models/page.tsx`

该页面将由以下几部分构成：

1. **顶部操作区**：
   - 标题与描述。
   - 「添加新模型」按钮，点击弹出新建表单弹窗。

2. **核心表格 (Table)**：
   - 展示字段：展现名称 (`name`)，底层模型ID (`model_id`)，请求地址 (`base_url`)，状态 (`enabled`)，权重/优先级 (`priority`)。
   - **操作列**：提供「编辑」和「删除」下拉菜单。

3. **新建/编辑弹窗 (Dialog Form)**：
   包含以下必填及选填表单项：
   - **名称 (Name)**: 例如 "DeepSeek V3 (官方)"
   - **模型 ID (Model ID)**: 例如 "deepseek-chat"（必填，必须和提供商严格一致）
   - **接口地址 (Base URL)**: 例如 "https://api.deepseek.com/v1"
   - **API Key**: 密钥字符串（编辑时可留空，代表不修改原密钥）
   - **能力标签 (Capabilities)**: 提供多选 Checkbox（`fast` 适合普通问答, `reasoning` 适合深度思考, `classifier` 适合路由分发）。系统就是靠这个来智能路由的！
   - **是否启用 (Enabled)**: Switch 开关。

---

## 4. 数据流与最终效果

1. 管理员在 `/admin/models` 点击「添加模型」，填入任意第三方兼容 OpenAI 格式的模型（比如硅基流动、月之暗面、或者 Ollama 本地模型）的 URL 和 Key。
2. 提交后，前端发送 `POST /api/v1/admin/models`。
3. 后端持久化到 `system_llm_configs`，原密码加密存储。
4. **效果**：系统中的任何用户，去到他们自己的「模型配置页」，下拉菜单里就会立刻多出这个新添加的模型供他们选用！

---

## 5. 验证计划

1. **后端验证**：在后端 `admin.py` 写好路由后，先检查 Python 是否报错，确保路由挂载成功。
2. **添加测试模型**：通过管理员界面添加一个伪造的模型（如 `Test-LLM`），保存成功后列表实时呈现。
3. **客户端可见性验证**：切回普通用户视角，进入主程序的 `/model-config`，核实下拉列表中是否已出现刚添加的 `Test-LLM`。
