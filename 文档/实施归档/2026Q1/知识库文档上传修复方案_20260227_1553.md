# 知识库文档上传失败问题分析与修复指南

## 🐛 问题原因分析

目前知识库的文档上传接口会返回 `422 Unprocessable Entity`，报错内容为 `{"success":false,"error":"请求参数验证失败","details":[{"type":"missing","loc":["body","file"],"msg":"Field required"}],"code":422}`。

这是因为 Next.js 前端 (BFF 层) 在将浏览器的 `multipart/form-data`（文件上传）请求代理转给后端 FastAPI 时，**破坏了请求格式和请求头**：

1. **请求头被强行覆盖为 JSON**：在 `jushi_agent/src/lib/api/proxy.ts` 中，代理默认合并了包含 `'Content-Type': 'application/json'` 的 `DEFAULT_HEADERS`。即便是文件流，后端收到的 Content-Type 仍是 `application/json`，导致 FastAPI 根本不去按照文件格式解析，自然找不到 `file` 字段。
2. **二进制文件流被错误地作为文本读取**：`proxyToBackend` 处理 body 时默认使用了 `await clonedRequest.text()`。这不仅丢失了 `FormData` 特有的边界格式 (boundary)，还会将纯二进制的文件解析成乱码字符串，造成严重损坏。

---

## 🛠️ 给 Codex 的修复要求

请让 Codex 修改 `jushi_agent/src/lib/api/proxy.ts`，使其兼容 `multipart/form-data`：

### 修改 `proxyToBackend` 的处理逻辑：

```typescript
    // ✅ 1. 判断是否是文件表单上传请求
    const sourceContentType = request.headers.get('content-type') || '';
    const isMultipart = sourceContentType.includes('multipart/form-data');

    // 构建请求头
    const requestHeaders: Record<string, string> = {
      ...DEFAULT_HEADERS,
      ...headers
    };

    // ✅ 2. 【核心修复】如果是表单/文件流，不能发送 application/json
    // 需要删除代理配置的默认 Content-Type，让稍后的 fetch 操作自动生成包含正确 boundary 的头部
    if (isMultipart) {
      delete requestHeaders['Content-Type'];
    }

    // ... (中间这段保留现有的鉴权 Token 等逻辑) ...

    // ✅ 3. 【核心修复】构建请求体时分流读取
    let requestBody: any;
    if (body) {
      requestBody = typeof body === 'string' ? body : (body instanceof FormData ? body : JSON.stringify(body));
    } else if (request.method !== 'GET' && request.method !== 'HEAD') {
      if (isMultipart) {
        // 如果是文件上传请求，通过 formData() 提取以保留二进制文件信息
        requestBody = await request.formData();
      } else {
        // 原有逻辑：直接读取为 text 文本
        const clonedRequest = request.clone();
        requestBody = await clonedRequest.text();
      }
    }
```

### 为什么这样改？
采用 `request.formData()` 获取原生表单对象后把它当成 `fetch` 的 `body` 传过去，同时我们删除了手动指定的 `Content-Type`，这样 Node 环境下的 `fetch` 就会识别到它是 `FormData` 并**自动帮你计算生成**包含独有 `boundary=xxxx` 字符串的正确 `multipart` Header，FastAPI 收到后就能成功拿到你上传的文件了，快去秒杀 Codex 吧！
