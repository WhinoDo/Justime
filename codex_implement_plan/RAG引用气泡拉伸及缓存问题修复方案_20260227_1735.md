# 修复 RAG 引用气泡错位及知识库未调用的问题分析与修复方案

## 🐛 问题原因深入分析

你遇到的这两个问题，背后的核心逻辑是不一样的，我们来逐个击破：

### 1. 为什么“引用文档”的框像面条一样拉满了全屏（只错位）？
这是由于在控制消息气泡渲染的文件（`MessageBubble.tsx`）中，前端给“引用文档”所在的那个 `div` 容器加上了 `w-full` （占满父容器100%宽度）这个 Tailwind 类。
本来因为消息文字很短，气泡本身已经缩窄了，但因为下面的引用框带有强制撑满的 `w-full`，它硬拉着外层不可见的 Flex 容器扩张到了最大限制（屏幕宽度的 85%），这就导致了你看到的极不协调的“拉长条”错位现象。

### 2. 为什么依然没有调用扫描版 PDF 知识库（只引用了 README）？
我们的 OCR 升级代码已经生效，但**旧的错误向量索引缓存还存在**！
后端的 `rag_service.py` 内部有一个缓存机制：只要它检测到系统里有之前生成的 `docstore.json`，它就会直接加载原来的老知识库（也就是空壳子的那份），而**跳过了**我们新加的 OCR 解析流程！这也是为什么它只能从仅剩下的 `README.md` 里强行找答案。

## 🛠️ 给 Codex 的双管齐下修复指南

请将这部分给 Codex，分两步彻底解决问题：

### 第一步：修复前端布局错位 (MessageBubble)
请修改 `src/components/chat/MessageBubble.tsx` 文件，找到大约第 224 行渲染 `ragReferences` 的地方：

把原先带有 `w-full` 的那一行：
```tsx
        {/* ===================== 修改前 ===================== */}
        {!isUser && message.ragReferences && message.ragReferences.length > 0 && (
          <div className="w-full max-w-full rounded-xl border border-blue-200/80 bg-blue-50/70 p-3 dark:border-blue-900/60 dark:bg-blue-900/20">
```

**改成自适应宽度 (`w-fit`) 且增加一些最大限制**：
```tsx
        {/* ===================== 修改后 ===================== */}
        {!isUser && message.ragReferences && message.ragReferences.length > 0 && (
          <div className="w-fit max-w-[100%] rounded-xl border border-blue-200/80 bg-blue-50/70 p-3 dark:border-blue-900/60 dark:bg-blue-900/20">
```
*（只需要把 `w-full` 改成 `w-fit` 即可，这样它就会像气泡一样优雅地贴合内容宽度了！）*

### 第二步：强制刷新后端 RAG 索引缓存
这部分**不需要改代码**，请你在终端（或者让系统自动）执行删除缓存文件夹的命令，来强制后端在新配置下重启扫描：

需要把后端中残存的旧向量存储删除，请进入 `jushi_backend` 目录，执行：
```bash
rm -rf app/data/storage
```
这会干掉旧缓存。然后**重启一次后端的 Python 服务**（`python start.py`）。
下次启动时，系统发现缓存没了，就会开始重新通过最新的 PyTesseract OCR 逐页提取 `串.pdf` 的内容并生成新的强大索引！

快去试着运行这些步骤吧！
