# 日程视频解析链路改造方案（Paraformer-v2 + DeepSeek Reasoner）

## 摘要
将“日程管理里的视频解析与分析”从 `faster-whisper + 自动 DeepSeek 选择` 改为固定链路：
1. 转写：`paraformer-v2`（阿里云百炼异步语音识别）。
2. 总结：`deepseek-reasoner`（固定使用 R1）。
3. 音频传输：提取后的音频先上传到私有 OSS，再用短时签名 URL 给 paraformer，任务结束后删除 OSS 临时对象。
4. 失败策略：严格失败，不回退旧链路。

## 影响文件
1. 核心后端服务：`jushi_backend/app/services/youtube_summary_service.py`
2. 配置定义：`jushi_backend/app/core/config.py`
3. 环境变量示例：`jushi_backend/.env.example`
4. 依赖声明：`jushi_backend/requirements.txt`
5. 前端阶段文案：`jushi_agent/src/components/calendar/EventDialog.tsx`
6. 单元测试：`jushi_backend/tests/services/test_youtube_summary_service.py`

## 对外接口/类型变化
1. 现有 API 路由不变（`POST/GET /calendar/events/{id}/youtube-summary/jobs` 无请求结构变化）。
2. `youtube_summary_jobs.currentStage` 新增阶段值：
   - `running/uploading_audio`
   - `running/asr_submitting`
   - `running/asr_polling`
3. 新增后端环境变量：
   - `DASHSCOPE_API_KEY`
   - `DASHSCOPE_BASE_URL`
   - `DASHSCOPE_ASR_MODEL`（默认 `paraformer-v2`）
   - `DASHSCOPE_ASR_TIMEOUT_SECONDS`
   - `ALIYUN_OSS_ENDPOINT`
   - `ALIYUN_OSS_BUCKET`
   - `ALIYUN_OSS_ACCESS_KEY_ID`
   - `ALIYUN_OSS_ACCESS_KEY_SECRET`
   - `ALIYUN_OSS_PREFIX`
   - `ALIYUN_OSS_SIGNED_URL_EXPIRES_SECONDS`
4. 总结模型选择规则改为固定 `deepseek-reasoner`，不再自动推断其他模型。

## 实施方案（决策完成版）
1. 在 `YouTubeSummaryService` 中移除本地 Whisper 转写路径：
   - 删除/废弃 `LOCAL_WHISPER_*` 与 `_transcribe_audio_sync` 模型缓存逻辑。
   - 保留 `_transcribe_audio`，内部改为远端 paraformer 流程。
2. 增加 OSS 上传与签名 URL 能力：
   - 使用 `oss2` 上传 `audio.wav` 到 `ALIYUN_OSS_PREFIX/{job_id}/{item_idx}.wav`。
   - 生成短时 GET 签名 URL（默认 3600 秒）给 paraformer。
   - 无论成功失败都执行对象删除。
3. 增加 paraformer 异步任务调用：
   - `POST /api/v1/services/audio/asr/transcription` 提交 `file_urls`。
   - 解析 `task_id`。
   - `GET /api/v1/tasks/{task_id}` 轮询直到 `SUCCEEDED` / `FAILED` / 超时。
   - 成功后读取结果并拼接全文 transcript。
4. 统一 transcript 拼接规则：
   - 将 paraformer 结果按时间/顺序拼接为纯文本（换行分段）。
5. 锁定总结模型为 `deepseek-reasoner`：
   - 在 `_resolve_summary_llm_config` 中只接受 `model_id == deepseek-reasoner` 的启用配置。
   - 若数据库无可用配置，则仅允许 `DEEPSEEK_API_KEY + DEEPSEEK_BASE_URL + deepseek-reasoner` 兜底。
   - 都缺失则直接失败（严格失败策略）。
6. 运行时依赖校验调整：
   - 去掉 `faster-whisper` 检查。
   - 新增 DashScope 和 OSS 配置完整性检查。
7. 文档写入元数据更新：
   - `_build_summary_block` 中“转写模型”更新为 `paraformer-v2 (DashScope ASR)`。
8. 前端状态展示补齐：
   - `EventDialog` 中增加新阶段中文文案，避免空白状态。
9. 依赖与配置同步：
   - `requirements.txt` 增加 `oss2`。
   - `.env.example` 增加 DashScope/OSS 必填变量示例。

## 测试与验收
1. 单元测试覆盖：
   - 提交任务成功
   - 轮询成功
   - 任务失败抛错
   - 超时抛错
   - 结果为空抛错
   - OSS 清理执行
2. 服务级回归：
   - `test_model_router_service.py` 不改动，继续回归验证。
3. 手工 E2E：
   - 创建含 YouTube 资源的日程事件。
   - 触发解析。
   - 验证阶段流转：
     `downloading -> extracting_audio -> uploading_audio -> asr_submitting -> asr_polling -> summarizing -> writing_document -> completed`。
   - 验证工作文档中包含：
     - 总结模型：`deepseek-reasoner`
     - 转写模型：`paraformer-v2`
4. 失败场景：
   - 配置错误 DashScope key，确认任务进入 `failed` 且错误可读。
   - 确认未触发 whisper 回退。

## 假设与默认值
1. 模型固定为：`paraformer-v2 + deepseek-reasoner`。
2. OSS 使用私有桶 + 签名 URL，签名有效期默认 3600 秒。
3. paraformer 采用官方异步任务接口，轮询超时默认 900 秒。
4. 不修改现有 API 入参结构，不引入数据库 schema 迁移。
